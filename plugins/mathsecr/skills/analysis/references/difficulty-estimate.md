# 새로 만든 문제의 난이도 추정·적정성 판단

사용자가 글이나 이미지로 준 문제(수학비서에 없는 문제)가 수학비서 난이도(1~9)로 어느 정도인지, 같은 단원의 수학비서 문항과 비교해 추정한다. 목표 난이도를 주면 적정한지도 판단한다. **결과는 Claude 추정이다. 수학비서가 매긴 난이도가 아니다.** 수학비서 문항이 아니므로 `similar_cells` 는 쓸 수 없다.

1. **단원 찾기.** 문제가 다루는 개념과 조건을 보고 `chapter_tree` 로 5단계 단원을 고른다(4단계 제목을 `keyword` 로 `depth: 5`). 사용자가 비슷한 수학비서 문항 ID 를 함께 주면 그 문항 `chapters[].id` 로 `chapter_tree(chapterIds)` 를 부른다. 고른 단원의 경로를 보여 준다. 두 단원이 비슷하게 맞으면 둘 다 적고 더 가까운 쪽을 쓴다.
2. **가설.** 문제의 구조(풀이 단계 수, 경우 나누기, 조건 해석, 계산량, 낯선 설정)를 보고 처음 추정 `d0` 을 정한다. 이 단계는 Claude 해석이다.
3. **단원 분포.** `cell_count(breakdown: "difficulty", curriculumId, chapterTreeIds, problemBankScope: "include", minDifficulties)` 를 1회 부른다. 기준은 d0-1·d0·d0+1·d0+2 중 1~9 안의 값이다(예: d0=4 → [3,4,5,6], d0=1 → [1,2,3]). `ranges` 가 d0-1·d0·d0+1 의 정확한 수와 (d0+2)~9, `totalCount` 가 전체다. 기준이 1 로 시작하지 않으면 전체 − 첫 기준 `atLeast` 를 「1~(d0-2)·난이도 없음」 한 칸으로 적고, 1 로 시작하면 `noDifficulty` 가 「난이도 없음」이다. `count` 가 null 인 칸은 「확인 실패(<reason>)」로 적고 채우지 않는다(`derived_zero` 는 0 이다). `consistent` 가 false 면 그대로 적는다. `minDifficulty = maxDifficulty = d` 로 센 수를 더하지 않는다(같은문제 묶음이 두 칸에 들어갈 수 있다). `include` 로 센 수에는 이 계정 문제은행 상태(`whoami`, 조회 시점)를 각주로 적는다(이용 중이 아니면 보유·공용 문항만). 분포가 비거나 아주 작으면(전체 10문항 미만) 4단계 부모 단원으로 넓혀 1회 더 부르고 밝힌다. `cell_count` 는 한 번에 하나씩 부른다. 도구 목록에 `cell_count` 가 없으면(예전 서버) `cell_search(limit: 1)` 로 전체 수와 같은 기준의 `minDifficulty`(`maxDifficulty` 없이) `totalCount` 를 읽어 차로 계산한다.
4. **기준 문항(앵커) 고르기.** 같은 단원에서 `d0-1`, `d0`, `d0+1` 문항을 `cell_search(limit: 5, excludeSubQuestions: true, excludePassageQuestions: true)` 로 찾는다. 비어 있는 난이도는 `d0±2` 로 넓힌다. 1~9 밖의 난이도는 검색하지 않고, 추정 범위도 1~9 안에서 낸다.
   - `hasPermission: true`, `isUnavailable: false` 인 문항만 쓴다. 「문제은행 구독 필요」(`isProblemBank: true`·`hasPermission: false`)·「문제은행에서 빠진 문항」은 앵커로 쓰지 않는다. 서로 다른 출처를 우선한다.
   - 앵커의 난이도는 `difficulty.mathSecr` 최댓값으로 본다. 검색 필터는 소문항마다 회원 값을 먼저 쓰고 그 최댓값으로 거르므로, 후보의 mathSecr 값이 찾던 난이도와 다르면 쓰지 않는다.
   - 숫자변형(NC)·같은문제(PC) 묶음은 난이도가 복사된 경우가 많아 서로 독립된 앵커가 아니다. 고른 앵커마다 `cell_detail` 로 `relations` 를 읽어, 한 앵커의 ID 가 다른 앵커의 PC·NC 목록에 있으면 하나만 쓴다(앵커 4개면 `cell_detail` 4회). 읽지 못했거나 `relations` 가 비었거나 잘렸으면 결과에 「앵커 간 같은 묶음 여부 미확인」이라고 적는다. `relations` 에는 문제은행 문항이 없어 문제은행 앵커끼리의 묶음은 확인되지 않는다. 문제은행 앵커(`isProblemBank: true`)가 둘 이상이면 「앵커 간 같은 묶음 여부 미확인」이라고 적는다.
   - 저장 난이도는 담당자 입력값, 연결된 문항에서 복사된 값, 또는 기본값(4)일 수 있고, 데이터만으로는 어느 쪽인지 알 수 없다. 앵커를 여럿 써서 한 문항 값에 기대지 않는다.
5. **판독.** 앵커의 문제 이미지(`parts: ["question"]`)를 순차로 읽는다. 기본 4장(`d0-1` 1장, `d0` 2장, `d0+1` 1장). 경계가 애매하면 이유를 밝히고 8장까지 늘린다. 8장을 넘기기 전에는 묻는다. 해설은 읽지 않는다.
6. **비교.** 새 문제를 각 앵커와 같은 기준(풀이 단계 수, 경우 수, 조건 해석, 계산량, 함정)으로 비교한다. "앵커보다 쉽다/비슷하다/어렵다"를 앵커마다 정하고, 위아래로 끼워 넣어 점수를 정한다.
7. **결론.** 점 추정과 범위를 낸다. 점 추정은 1~9 정수, 기본 범위 ±1, 1~9 밖은 잘라 낸다(예: 점 1 → 범위 1~2). 앵커가 부족하거나 판단이 엇갈리면 ±2 로 넓히고 이유를 적는다.

## 적정성 판단 (목표 난이도를 준 경우)

- 점 추정이 목표와 같으면 「적정」.
- 목표가 추정 범위 안에 있지만 점 추정과 다르면 「경계(조정 권장)」이고 방향을 함께 쓴다. 점 추정 < 목표면 "목표보다 조금 쉬움 — 한 단계 어렵게", 점 추정 > 목표면 "목표보다 조금 어려움 — 한 단계 쉽게".
- 추정 범위 전체가 목표보다 높으면(새 문제가 더 어려움) 「목표보다 어려움」, 전체가 낮으면 「목표보다 쉬움」.
- 범위를 ±2 로 넓혔으면 판정 옆에 "추정 폭이 넓음"을 적는다. 모두 「Claude 제안」으로 적는다.
- 「적정」이 아니면 판정의 방향(어렵게/쉽게)과 같은 쪽으로만 바꿀 점을 앵커와 비교해 한두 가지 제안한다(예: 단계를 하나 더 넣기, 경우 하나 없애기). 「적정」이면 조정을 권하지 않는다.

## 결과 (아래 틀을 순서대로 채운다. 틀은 읽기 쉽게 코드 블록에 두었을 뿐이니 답에는 코드 블록 없이 채운다. 칸을 빼거나 판정 라벨을 바꾸지 않는다)

```
**결론** 「Claude 추정 — 수학비서 난이도 아님」 난이도 <점>(범위 <a>~<b>)
목표 <t>: 「적정」|「경계(조정 권장)」|「목표보다 어려움」|「목표보다 쉬움」 중 하나 (Claude 제안) — <방향 한 줄; 「적정」이면 생략; ±2면 "추정 폭이 넓음">
이유: <한 줄. 가장 가까운 앵커와 비교한 근거(앵커 ID) 또는 분포상 위치>

**단원 분포** 「수학비서 데이터」 cell_count.ranges·totalCount, tree_id <ID>, problemBankScope include, minDifficulties <기준>
| 1~(d0-2)·난이도 없음 | d0-1 | d0 | d0+1 | (d0+2)~9 | 전체 |

**앵커**
| 앵커 ID | 난이도 | 구조 요약 | 새 문제와 비교 |

**바꿀 점** (「적정」이 아닐 때만, 판정 방향으로 한두 가지)

각주
1. include 로 센 수다. 이 계정 문제은행: 「이용 중」|「이용 중 아님」|「확인 불가」(whoami, 조회 시점). 이용 중이 아니면 보유·공용 문항만 센 수다(확인 불가면 「구독 상태에 따라 다름」).
2. 앵커 간 같은 묶음: 확인함 | 「앵커 간 같은 묶음 여부 미확인」(이유)
3. 이 추정의 정확도는 따로 검증되지 않았다.
4. 이미지 <n>장 사용, 잔액 <r>(cell_image.budgetRemainingToday)
```

- 목표를 주지 않았으면 판정 줄과 바꿀 점을 뺀다. 분포 칸 이름은 실제 난이도로 쓴다(예: d0=4 → 1~2·난이도 없음 | 3 | 4 | 5 | 6~9 | 전체). 기준에 1 이 들면 「난이도 없음」을 따로 한 칸으로 둔다. 확인 실패 칸은 「확인 실패(<reason>)」로 둔다.
- 앵커 난이도 칸: 「수학비서 데이터」 `cell_search.answerMetadata` + ID. 구조·비교 칸: 「이미지 판독(Claude 해석)」 cellId + part + 판독자.
- 정답·풀이를 쓰지 않는다. 새 문제도 답을 풀어 보이지 않는다(필요하면 구조만 말한다).
- 수학비서의 저장 난이도가 필요하면, 수학비서 웹에서 나만의 DB 로 올려 DB화한 뒤 `mydb_cells` 로 문항별 난이도를 읽을 수 있다고 안내한다. 그 값도 위 4번처럼 담당자 입력·복사·기본값일 수 있다. Claude 가 올려 줄 수는 없다.
