# 단원 자료 한꺼번에 받기 (분포·ID 목록·이미지)

"이 단원 자료를 전부 받고 싶다"는 요청을 처리한다. MCP 에는 일괄 내보내기·다운로드가 없다. 먼저 규모와 비용을 알리고, 분포 → 범위 좁히기 → ID → 이미지 순서로 나눠 준다.

1. **단원 확정.** `chapter_tree` 로 단원을 찾는다. 같은 이름 단원이 여럿이면 `nodePath`·`tree_id` 로 나눠 표로 보여 주고 각각 따로 센다. 별칭 단원(`isAlias`)은 `originTreeId` 를 쓰고 원본 단원이 어디인지 밝힌다. 원본이 이미 고른 단원이면 한 번만 센다. 원본이 다른 단원이면 그 원본도 따로 세는 단원 하나로 보고 2·3번을 똑같이 한다(단원마다 `cell_count` 1회, 두 단원 ID 를 한 호출에 함께 넣지 않는다). 표와 근거의 단원 ID 는 검색에 넣은 `chapterTreeIds` 값(별칭이면 원본 ID)으로 쓰고, 별칭 ID 는 단원 확정 줄에 「별칭 <별칭 ID> → 원본 <원본 ID>」로 한 번만 적는다.
2. **규모·난이도 분포.** `cell_count(breakdown: "difficulty", curriculumId, chapterTreeIds: [단원 ID], problemBankScope)` 를 1회 부른다(`minDifficulties` 는 비워 기본 [1,3,5,7]). `totalCount` 가 전체 수, `ranges` 가 웹의 난이도 4단계(쉬움 1-2·보통 3-4·어려움 5-6·매우 어려움 7-9) 칸, `noDifficulty` 가 「난이도 없음」이다. 범위(`problemBankScope`)를 밝히고, `include` 면 이 계정 문제은행 상태(`whoami`, 조회 시점)를 각주에 적는다(이용 중이 아니면 보유·공용 문항만). `cell_count` 는 한 번에 하나씩 부른다(병렬 금지).
3. **분포 읽기.** `count` 가 null 인 칸은 「확인 실패(<reason>)」로 적고 채우거나 이웃 칸에서 계산하지 않는다. `reason: "derived_zero"` 는 전체나 더 낮은 기준이 0이라 0으로 둔 값이다. `consistent` 가 false 면 그대로 알린다. 사용자가 1~9 한 칸씩을 원할 때만 `minDifficulties` `[2,4,6,8]` 로 한 번 더 부르고, 8 과 9 를 나눠야 할 때만 `[9]` 를 한 번 더 부른다(1·3·5·7 은 2번 값을 쓰고 다시 읽지 않는다). 칸 d = `atLeast` d − `atLeast` d+1(1~8, 두 호출의 값을 함께 쓴다), 9 칸 = `atLeast` 9, `[9]` 를 부르지 않았으면 8~9 = `atLeast` 8 한 칸이다. 한 페이지 결과나 `minDifficulty = maxDifficulty = d` 로 센 수를 더해 분포를 내지 않는다(같은문제 묶음이 두 칸에 들어갈 수 있다). "호출이 너무 잦습니다" 오류면 다시 부르지 않고 센 데까지만 알린다. 도구 목록에 `cell_count` 가 없으면(예전 서버) `cell_search` `limit: 1` 로 전체 수와 `minDifficulty` 1·3·5·7(`maxDifficulty` 없이)의 `totalCount` 를 읽어 같은 칸을 차로 만든다(a~b = a 값 − b+1 값, 난이도 없음 = 전체 − 1 값).
   - 문항 난이도는 소문항마다 회원 값, 없으면 수학비서 값을 쓴 최댓값이다. 난이도 없는 문항은 minDifficulty 를 주면 빠지고 maxDifficulty 만 주면 들어온다. 같은문제 묶음은 묶음 안 가장 높은 값의 칸에 한 번 든다.
4. **하위 단원 분포.** 필요하면 하위(5단계) 단원 `tree_id` 2~4개를 `cell_count(breakdown: "chapter", chapterTreeIds)` 1회로 센다(2번과 같은 범위·필터). 하위 단원이 4개를 넘으면 모두 이름으로 나열하고, 요청에 나온 하위 단원이 있으면 그중 4개까지만 센다. 없으면 세지 않고 어느 단원(4개까지)을 셀지 묻는다. 세지 않은 단원은 「세지 않음」이다. 하위 단원이 하나뿐이면 나눠 세지 않는다. 한 문항이 여러 단원에 들 수 있어 하위 단원 수의 합이 전체보다 클 수 있다고 적는다. 센 단원이 둘 이상이면 하위 단원 분포는 세지 않고 6번에서 하위 단원으로 좁히기를 제안한다.
5. **비용 안내.** 다음을 먼저 알린다.
   - ID 목록: 한 번에 20개까지라 전체를 받으려면 약 `totalCount / 20` 번 조회해야 한다.
   - 이미지: 직접 판독은 회원 공용 하루 300장이다. 보기 링크는 한 번에 10문항까지 열린다.
   - 전체를 한 파일로 받는 기능은 MCP 에 없다. 필요하면 수학비서 웹을 이용한다.
6. **범위 좁히기.** 고난도만, 특정 하위 유형만, 특정 난이도만처럼 좁힌 범위를 제안하고, 좁힌 범위의 문항 수를 함께 보여 준다. 난이도로 좁힌 범위 a~b 의 문항 수는 7번에서 받을 검색 결과 수와 같아야 하므로 누적 값의 차로 내지 않는다: 같은문제 묶음은 필터 뒤에 합쳐져(난이도 3·7 이 든 묶음은 3~4 차에는 0, `minDifficulty: 3`·`maxDifficulty: 4` 검색에는 1) 차가 실제 검색보다 작을 수 있다. b 가 9 면 2번 `atLeast` a 가 그 검색(`minDifficulty: a` 만)과 같은 필터라 그대로 쓴다. b 가 8 이하면 최종 필터(`minDifficulty: a`·`maxDifficulty: b`)로 `cell_search` `limit: 1` 을 1회 불러 `totalCount` 를 쓴다(ID·이미지를 원하는 요청에서만, 제안 범위 2개까지. 세지 않은 제안은 「수는 범위를 고르면 센다」로 둔다). 3번 분포 칸(`ranges`·누적 차)은 개요로만 쓰고 이 수로 쓰지 않는다. 하위 단원별로 난이도까지 좁힌 수는 `cell_count(breakdown: "chapter", 하위 tree_id 2~4개, minDifficulty·maxDifficulty)` 1회로 센다(`minDifficulty: 1` 과 `maxDifficulty: 9` 를 함께 넣지 않는다). 전체가 100개(5페이지)를 넘으면 사용자가 범위를 고를 때까지 ID 목록과 보기 링크로 넘어가지 않고 여기서 답을 마친다. 요청의 "전부"는 범위를 고른 것이 아니다.
7. **ID 목록.** 좁힌 범위의 최종 필터로 `limit: 20` 새 검색을 시작해 `nextCursor` 로 페이지를 넘기며 ID 를 모은다(앞의 `cell_count` 집계와 별개로 처음부터 검색한다). 기본 5페이지(100개)까지 받고, 더 필요하면 이어 받을지 묻는다. 사용자가 원하면 25페이지(500개)까지 받을 수 있다. 대화가 길어지므로 Claude Code 에서는 이 수집을 `question-scout` 에 맡긴다.
8. **이미지.** 보기 링크는 한 번에 10개씩, 처음에는 한 묶음만 만들고 더 필요하면 묻는다. 모아 둔 ID 에서 「문제은행 구독 필요」·「문제은행에서 빠진 문항」·권한 없음·사용 불가 ID 는 빼고, 남은 ID 를 `cell_image_link` 에 10개씩 나눠 보기 링크를 만든다. 여러 문항을 한꺼번에 `cell_image` 로 판독하지 않는다.

## 결과

- 답 맨 앞 1~2줄(표보다 앞)이 결론이다: 「MCP 에는 단원 전체를 한꺼번에 내보내는 기능이 없음(수학비서 웹)」과 센 단원마다 단원 ID·전체 수(`cell_count.totalCount`, 별칭이면 원본 ID)를 쓰고, 이어서 다음 단계(범위 고르기)를 적는다. 멈춘 이유·규칙 설명은 그 뒤에 둔다.
- 규모·분포 표 아래에 `「수학비서 데이터」` 문구를 그대로 쓰고 `cell_count.totalCount`·`ranges`·`noDifficulty` 와 그때 쓴 필터(단원 ID·기준 `minDifficulties`·범위)를 적는다. 분포 표 칸은 쉬움 1-2 · 보통 3-4 · 어려움 5-6 · 매우 어려움 7-9 · 난이도 없음 · 전체다(기준을 바꿨으면 실제 구간으로). 분포 표에는 「누적 수의 차(개요)」라고 적고, 6번에서 좁힌 범위의 수는 그 검색의 `totalCount` 로 따로 적는다. 확인 실패 칸은 「확인 실패(<reason>)」로 둔다.
- 단원이 둘 이상이면 규모·분포 표를 단원마다 한 행으로 나누고 행의 단원 ID 는 그 행을 센 값 하나로 통일한다. 세지 않은 칸은 「세지 않음」으로 적는다.
- 받은 ID 수(쓸 수 있음 N / 열 수 없음 M, 사유별)와 전체 수를 함께 적는다(예: 100(쓸 수 있음 96 / 문제은행 구독 필요 4) / 3,598).
